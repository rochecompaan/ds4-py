# Post-8,192 Bake-off Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make request-limit failures reproducible and restorable, align directory discovery with the shell, repair acceptance probes, and gather repeatable live evidence before another full bake-off.

**Architecture:** Keep production request-limit behavior in `AgentRuntime` and failed-history reconciliation in `MessageBinder`. Keep benchmark policy in the CLI and bench configuration. Reuse the existing task runner for independent live repetitions and the existing TUI event stream for interruption timing.

**Tech Stack:** Python 3.14, Pydantic AI, pydantic-ai-harness, prompt-toolkit, pytest, Pyright, Ruff.

**Spec:** `docs/specs/2026-10-31-bakeoff-8192-fixes-design.md`

## Global Constraints

- Preserve nonzero exits for `max_tokens`, `parser_error`, and request-limit exhaustion.
- Keep `AgentRuntime`'s production request-limit default at 50; use 100 explicitly for the CLI and bake-off.
- Remove `list_directory` only from ds4-py's configured toolset; do not patch the dependency or add discovery instructions.
- Run each failed task at least three times in a fresh process and workspace; do not stop after the first pass.
- Do not relax save validation, replay comparison, or clean-terminal requirements.
- Do not create a paid GPU instance automatically and do not start a full bake-off before targeted checks pass.
- Commit each task separately.

## Review Focus

- A bound trailing tool request must survive failure reconciliation, while the first unexecuted request must be excluded; Task 2 covers both cases.
- C must not receive the ds4-py-only `--request-limit` flag; Task 2 covers command construction.
- Hidden files must remain discoverable through `run_command` after `list_directory` is removed; Task 3 covers the real toolset and shell behavior.
- Startup prefill and `run_start` must not trigger Ctrl-C, while the first token must do so; Task 4 covers the lifecycle transition and PTY steps.
- A targeted pass must not reduce the number of repetitions; Task 5 proves three fresh result roots and one attempt per root.
